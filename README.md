# Project Paradise Backtester

Student-oriented backtesting and strategy hypothesis testing tool, built on a fork of [vectorbt](https://github.com/polakowo/vectorbt).

**Tech Stack:** Python | Docker | Library Development

## What it adds on top of vectorbt

- **`bt` CLI** — run, store, inspect, compare, and report on backtests from the command line
- **Run registry** — every backtest is content-addressed by a hash of its config and stored with its metrics, artifacts, and environment info; identical configs are deduplicated
- **Permutation testing** — statistical validation of strategy results against a null distribution built by permuting price returns (Masters-style) or shuffling signals

## Installation

```bash
cd vectorbt
pip install -e .
```

This installs the vectorbt fork plus the `bt` console command.

## Quickstart

A strategy is a Python file with a top-level `run(data)` function that returns a `vbt.Portfolio`:

```python
# sma_cross.py
import vectorbt as vbt

def run(data):
    close = data["Close"]
    fast = vbt.MA.run(close, 10)
    slow = vbt.MA.run(close, 30)
    entries = fast.ma_crossed_above(slow)
    exits = fast.ma_crossed_below(slow)
    return vbt.Portfolio.from_signals(close, entries, exits, init_cash=10_000, fees=0.001, freq="1D")
```

Run it against data from CCXT, Yahoo Finance, or a CSV file:

```bash
bt run --source ccxt --exchange binance --symbol BTC/USDT --interval 1h \
       --start 2024-01-01 --end 2024-06-01 --strategy sma_cross.py

bt run --source yfinance --symbol TSLA --interval 1d \
       --start 2024-01-01 --end 2024-12-31 --strategy sma_cross.py

bt run --source csv --file data.csv --symbol TEST/USD --strategy sma_cross.py
```

Then work with stored runs (any unique run-id prefix is accepted):

```bash
bt list                          # table of all runs
bt list --sort sharpe --filter BTC
bt show 344b25                   # config, metrics, artifacts for one run
bt diff 344b25 0946a7            # side-by-side comparison of two runs
bt report 344b25 --open          # self-contained HTML report with charts
bt permute 344b25 --n 1000       # permutation test for statistical significance
```

## Permutation testing

`bt permute` answers the question: *could my strategy's performance have come from luck?*

It re-runs the strategy against many permuted price paths (per-bar log returns are shuffled and recompounded, preserving the return distribution and overall drift while destroying any temporal structure), builds a null distribution for each metric, and reports p-values:

```
Metric                  Observed   Null Mean   Null Std  Percentile    p-value   Sig
─────────────────────────────────────────────────────────────────────────────────────
sharpe_ratio              1.8421      0.0513     0.6112       99.6%     0.0080   ***
total_return              0.4210      0.0090     0.1392       99.2%     0.0160    **

Significance: *** p<0.01  ** p<0.05  * p<0.10
Correction: bonferroni
```

Multiple-testing correction is applied across metrics (`--correction bonferroni|holm|none`).

## Run registry layout

Each run is stored under a deterministic ID (`sha256` of its canonical config):

```
bt_runs/
  registry.json                  # index of all runs
  runs/<run_id>/
    config.json                  # canonical run configuration
    metrics.json                 # extracted performance metrics
    versions.txt                 # environment provenance
    returns.parquet              # per-bar and cumulative returns
    equity.parquet               # equity curve and drawdown
    trades.csv                   # trade log
    report.html                  # generated by `bt report`
    permutation.json             # generated by `bt permute`
```

The registry is also usable as a library:

```python
from vectorbt.registry import Registry

reg = Registry(base_dir="bt_runs")
entry = reg.create(config, summary=metrics)
runs = reg.list(sort_by="sharpe", filter_by="BTC")
diff = reg.compare(run_id_1, run_id_2)
```
